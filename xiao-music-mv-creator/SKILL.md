# 晓·音乐 MV 创作

把一支片子拆成能单独生成、能接回时间线、能检查和返工的镜头。维护各项目自己的设定与进度，以便打断后还能接上。

需要可以直接复制的提示词时，按当前阶段选用 [核心提示词库](references/prompt-library.md)。库中有写歌、出歌、分镜、静帧、图生视频、转场、预告剪辑、封面和验收模板，也有完整填好的项目示例。

## 找到本次交付

- **新片**：接受用户的随手想法与现有素材，先整理主题、用途、音乐版本或结构、片长、画幅、风格、必须保留项和本次交付。若音频可分析，用实际曲段和拍点；否则用用户给的时间点，或明确标为暂定。缺少关键选择时，只问最影响下一步的一项；可并行做不依赖该答案的工作。
- **MV 预告片**：从现有 MV 素材剪预告，或以已有音轨和少量关键镜头先做预告。按用户指定时长、平台和透露程度交预告分镜、剪辑时间线或成片。读 [MV 预告片](references/mv-teaser.md)。
- **续做或回退**：先查项目的有效设定、分镜、资产和状态表，项目记录缺失时采用用户本轮明确给出的有效状态，未知项标为待核。简短报「当前节点、使用哪版、这次交什么」。用户说「继续」且状态只有一个下一步，就接着做。只有歧义影响本次交付或用错版本时才问一句。读 [状态与回退](references/project-state.md)。
- **定向修改或检查**：按用户指定的段号、镜号或资产做增量修改。从已有定稿恢复需要的约束；改动会影响后续首帧、视频或剪辑时，标出受影响结果和复核点。
- **限定输出**：区分执行包、静帧提示词、图片、图生视频提示词、视频片段、剪辑方案、预告和完整 MV。已有合格的上游输入可直接进入用户请求的阶段。要求交媒体时用当前可用且获准的能力实际交付；能力缺失时点明缺口，交付可执行的提示词或剪辑单作为替代，并标记该媒体未生成。未看到文件时不报告为生成或验收通过。

## 制作顺序与验收

**没有定稿音轨时，先准备歌曲。** 从用户的主题和情绪方向出发，整理歌词或器乐段落、风格、人声、编曲与曲式，按选定的工具准备出歌输入。试听候选、选定 MV 采用的音轨，再按实际音频标记入唱、曲段和关键切点。已有定稿音轨时直接登记并标记。读 [歌曲制作与音轨交接](references/music-track.md)。定稿前可以探索美术和草拟段落，分镜时间先标为暂定。

1. **锁定美术资产。** 用角色卡记录辨识特征、发型、服装、配饰位置、气质、定稿图及禁止变化；用场景卡记录空间布局、可辨认的锚点、光色、材质、可变特效及禁止变化。没有人物的镜头写清无角色入镜；产品为主时记录产品外观与标识。区分草稿和可用定稿。需要先探索时允许带假设做试镜，别把未定资产批量用于下游。
2. **先定主分镜，再拆短镜头。** 按音轨段落或叙事转折分配起止时间，写清情绪、主视觉和段间交接。若有母图，标明它锁定的元素、最接近的镜号及可变项，禁止把母图自动当作每一镜的首帧。将过长或动作过多的段落拆为易生成的镜头；A 建立、B 核心、C 收束是常用的三镜分工。依音乐与工具能力增减镜头，段数、时长、画幅和剧情由项目决定。
3. **逐段交执行包。** 用 [分镜与执行包](references/execution-pack.md) 写时间窗、前后段承接、母图用法、拍点、每镜任务、两种提示词、参数建议、通过标准与拼接方式。核对的是实际用在时间线上的时长；转场重叠或留白须可追溯。
4. **先验静帧，再图生视频。** 每条可独立投喂的静帧或视频提示词都要展开该镜适用的四层：**角色锁定、场景锁定、镜头任务、负面约束**。不能仅写「同前」「沿用角色卡」或留待用户回填的占位符。场景卡列出的物件按镜位取舍，保留能辨认空间且需持续一致的锚点，不为塞全清单破坏特写。静帧写单一时间点；图生视频指定已验静帧的文件或镜号、起始状态、主要运镜、运动对象与幅度、锁定项和收尾点。无审核合格首帧时可准备视频提示词，将实际生成标为等待首帧。每条提示词单独拿出去审一次。
5. **逐镜审、逐段拼、全片验。** 静帧看身份、空间和构图；视频看首尾、运动、变形和连续性；段落看情绪递进、是否提前消耗后段视觉、是否能接下一段；整片看音画、时长、转场、色彩、收尾。反馈写成「镜号 → 实际问题 → 对照标准 → 保留什么 → 局部修改 → 如何复验」。有可用素材和剪辑能力时交付用户请求的媒体；否则交付剪辑时间线或缺件清单。验收处理见 [分镜与执行包](references/execution-pack.md#验收与局部返工)。

## 可选：封面与发布素材

用户要求做封面、片名、字幕标题或发布介绍时，读 [封面与发布素材](references/cover-release.md)。保留原图和色彩与重新定版式可以同时成立；素材制作、文案交付和实际上线是不同动作，按用户授权执行。
