# 项目状态与回退

有工作区时维护一份项目自己的 `project-state.md`，复用用户现有的等价文档；只在聊天中交付时给简短可复制的状态摘要。每次交付、验收或回退后更新受影响的行。文件和版本只是索引，别把完整设定与提示词在状态表再抄一遍。

```text
项目 / 音轨版本 / 片长 / 画幅：
有效设定：角色卡…｜场景卡…｜主分镜…｜镜头表…
当前节点：第…段 / …镜｜要交的产物…
下一步：具体动作 + 镜号 + 等待条件（如有）
废弃版本 / 禁用资产：…
```

| 段或镜号 | 资产角色与版本 | 文件或可定位的消息 | 可参考范围 | 状态 | 验收结果或依赖 |
|---|---|---|---|---|---|
| 05 | 段落母图 v2 | `05_main_reference_v2.png` | 构图与空间，不锁定特效 | 当前 | 用户明确指定 |
| 05B | 静帧 v3 | `05B_static_v3.png` | 通过后作为 05B 首帧 | 待审 | 依赖角色卡 v2、场景卡 v1 |

资产角色包括角色定稿、场景定稿、段落母图、单镜静帧、视频和仅供参考素材。状态另列，例如草稿、待审、通过、待改、待复核、废弃。「用户上传」不等于「通过」。图片不清楚时先看用户标注、文件名和项目状态；剩下的歧义会影响使用方式时问「这张是第 05 段母图，还是 05B 待审静帧？」。没看到图时不评价其画面。

镜头 ID 统一用 `05A`、`05B`、`05C` 或项目已采用的编号；资产名尽量反映类型，如 `05_main_reference_v2.png`、`05A_static_v2.png`、`05A_video_prompt_v2.md`、`05A_clip_v1.mp4`。每份关键产物的 ID 与时间表、文件名一致。

## 版本冲突或回退

1. 以用户最近一次**明确选定**的基线和本次要求为准。区分「保留到第 04 段」与「从第 04 段重做」。回退范围不清且会影响交付时，只问这一处。
2. 记下「保留哪些有效版本｜放弃哪些分支或资产｜从哪个镜号和产物重启｜下一步」。将废弃项从后续引用中排除；保留历史，回退本身不等于删文件。
3. 用户明确废弃的下游素材直接标为废弃。未明确处置且依赖废弃首帧、角色卡或场景卡的素材标待复核。若更新后的标准仍能满足，可复用通过的内容；否则局部返工。

例：「第 04 段定稿后分叉的 05 段内容放弃，回到第 04 段之后。继续第 05 段执行包。」保留已确认的 01–04，排除旧 05 分支，使用仍有效的锁定资产重建 05 执行包；不把旧 05 静帧拿来当新母图，也不自动推进到出图。
